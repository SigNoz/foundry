# Kubernetes Kustomize + MCP

| Field | Value |
| --- | --- |
| **Mode** | `kubernetes` |
| **Flavor** | `kustomize` |
| **Platform** | `-` |

## Overview

The [Kustomize](../kustomize/README.md) deployment with the optional [SigNoz MCP server](../../../concepts/mcp-server.md) turned on, so AI clients (Claude Code, Claude Desktop, …) can query your telemetry. MCP is disabled by default; this example enables it.

> [!NOTE]
> This example is maintained by hand and is not regenerated by `foundryctl gen examples`.

## Configuration

```yaml
apiVersion: v1alpha1
kind: Installation
metadata:
  name: signoz
spec:
  deployment:
    flavor: kustomize
    mode: kubernetes
  mcp:
    spec:
      enabled: true
```

`enabled: true` is the only MCP field you set. The molding fills the rest.

## Deploy

```bash
foundryctl cast -f casting.yaml
```

## What gets generated

The manifests gain an `mcp/` directory with a Deployment and a ClusterIP Service on port `8000`, wired into the root `kustomization.yaml`. The env is filled in automatically (no API key in the casting):

```yaml
      containers:
      - env:
        - name: MCP_SERVER_PORT
          value: "8000"
        - name: SIGNOZ_URL
          value: http://signoz-signoz:8080
        - name: TRANSPORT_MODE
          value: http
        image: signoz/signoz-mcp-server:latest
```

The in-cluster endpoint is `http://signoz-mcp.signoz:8000/mcp`; expose it outside the cluster per your setup.

Verify it is up:

```bash
kubectl -n signoz get pods -l app.kubernetes.io/component=mcp
```

## Connect a client

Mint a SigNoz API key (SigNoz UI -> Settings -> API Keys) and point Claude Code or Claude Desktop at the MCP endpoint. Full steps, including the per-request `SIGNOZ-API-KEY` header and OAuth alternatives, are in [MCP server](../../../concepts/mcp-server.md).
