# Docker Compose + MCP

| Field | Value |
| --- | --- |
| **Mode** | `docker` |
| **Flavor** | `compose` |
| **Platform** | `-` |

## Overview

The [Docker Compose](../compose/README.md) deployment with the optional [SigNoz MCP server](../../../concepts/mcp-server.md) turned on, so AI clients (Claude Code, Claude Desktop, …) can query your telemetry. MCP is disabled by default; this example enables it.

> [!NOTE]
> This example is maintained by hand and is not regenerated by `foundryctl gen examples`.

## Configuration

```yaml
apiVersion: v1alpha1
kind: Installation
metadata:
  name: signoz
spec:
  deployment:
    mode: docker
    flavor: compose
  mcp:
    spec:
      enabled: true
```

`enabled: true` is the only MCP field you set. The molding fills the rest.

## Deploy

```bash
foundryctl cast -f casting.yaml
```

## What gets generated

The compose file gains a `signoz-mcp` service on port `8000`, with its env filled in automatically (no API key in the casting):

```yaml
  signoz-mcp:
    container_name: signoz-mcp
    image: signoz/signoz-mcp-server:latest
    networks:
      - signoz-network
    environment:
    - TRANSPORT_MODE=http
    - MCP_SERVER_PORT=8000
    - SIGNOZ_URL=http://signoz-signoz-0:8080   # the in-network SigNoz apiserver
    ports:
    - "8000:8000"
```

Verify it is up:

```bash
docker ps | grep signoz-mcp
curl -fsS localhost:8000/livez && echo " OK"   # -> 200
```

## Connect a client

Mint a SigNoz API key (`http://localhost:8080` -> Settings -> API Keys) and point Claude Code or Claude Desktop at `http://localhost:8000/mcp`. Full steps, including the per-request `SIGNOZ-API-KEY` header and OAuth alternatives, are in [MCP server](../../../concepts/mcp-server.md).
